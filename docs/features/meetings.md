# Meetings

Authenticated users own their meetings. APIs check ownership before accessing audio or metadata. Mutation requests require the application's Origin header. Audio uses private Vercel Blob and is served only through authenticated routes; database/Blob URLs and speaker references never reach the client.

Recordings are canonical WAV PCM16, mono, 16 kHz, split into parts of 105–120 seconds cut at the quietest 100 ms in that window so words are not split (final part may be shorter), up to 138 parts / four hours. Transcript timestamps and audio-part starts are the sum of earlier part durations, so older meetings with exact 120-second parts keep working. Each upload stays below Vercel's function body limit. Uploads are idempotent by meeting/index and SHA-256; conflicting content is rejected. Finish validates all expected parts are present and contiguous. Saved incomplete recordings can finish from the saved consecutive parts. Audio still only in the browser cannot be recovered after that browser data is lost.

Processing performs one transcription part per request, then one summary request, driven by the meeting page. A durable database lease expires after 270 seconds; the OpenAI request times out after 210 seconds. Lease tokens fence late results. Closing the page pauses processing; reopening resumes. Failed jobs retain their audio and transcript and expose an explicit retry. The application does not automatically retry billable failures indefinitely.

OpenAI `gpt-4o-transcribe-diarize` preserves the source language and returns timestamped speaker segments. Up to four 2–8 second non-overlapping speaker samples provide known-speaker references across parts. Unmatched speakers get part-scoped labels; speaker identity remains probabilistic and names are not inferred. `gpt-4.1` summarizes the whole transcript (consecutive same-speaker segments merged, plus title, date, duration and confirmed speaker names as metadata) in the predominant meeting language, using JSON output for a structured Markdown summary (summary, topics, positions, decisions, next steps, open questions and risks) and language. Silence produces a no-speech result. No transcript text is truncated before summarization.

Each meeting records its real OpenAI spend in `meetings.cost_usd`. Both providers return a `usage` object; `callCostUsd` in `src/lib/openai-pricing.ts` prices each response with its own model's list rate the moment it returns, and the result is added to a running total inside the lease-fenced write. Storing dollars rather than token counts freezes the price in force at call time, so a past meeting is never re-priced by a later rate change; the cost of that is that a mistake in the price table is not retroactively fixable. Retries and billed-but-discarded calls are included, so the figure reflects what was actually spent. `NULL` means usage was never captured — pre-existing meetings stay `NULL` and render nothing, never `$0.00`. Cost accounting never throws: unparseable or absent usage contributes zero and processing continues. List prices exclude tax, discounts and credits, and cover OpenAI only — not Blob storage or function compute. Measured on short single-part recordings: roughly USD 0.02 per minute, about three times the `$0.006/min` the pricing page quotes, because output tokens dominate; longer meetings cost more per minute still, since speaker references are re-sent as audio input on every part after the first.

Required server environment: POSTGRES_URL, BLOB_READ_WRITE_TOKEN (private store), OPENAI_API_KEY, existing Better Auth/Google settings. Run `pnpm db:generate` and `pnpm db:migrate` for schema changes, never `db:push`. Vercel processing routes request 240 seconds; the deployed plan must support that execution duration. Recordings require keeping the recording tab/device awake and browser permissions active.

Validation: `pnpm exec tsx scripts/check-meeting-core.ts` covers WAV boundaries, four-hour limits, complete chunk sequences and same-origin mutations. Full live provider checks require configured credentials, authenticated sessions and a sample recording; successful lint/build alone does not establish live transcription quality or four-hour endurance.

Official references: https://developers.openai.com/api/docs/guides/speech-to-text and https://developers.openai.com/api/docs/models/gpt-4.1.
